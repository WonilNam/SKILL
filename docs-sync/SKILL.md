# Documentation Sync

目标：让开发者文档成为当前代码的可验证入口，而不是复制实现或保留过期猜测。

## Source of Truth

按“公开接口与 schema -> 实现/配置 -> 测试和可运行示例 -> 现有文档”的顺序核对事实。冲突时记录差异，不自动把旧文档当规范，也不把实现偶然细节写成承诺。

## Workflow

1. 确定目标读者和任务：安装、快速开始、API 使用、故障排查、迁移或发布变化。
2. 搜索相关公开符号、字段、命令、配置键、废弃接口和成对文档（如 Markdown GUIDE 与 HTML GUIDE）。
3. 用最短可运行路径组织内容；代码示例必须完整、使用真实名称，并包含必要上下文和失败语义。
4. 同步所有受影响文档、示例和测试页面；删除废弃入口时先确认其确已从代码移除或明确标注兼容期。
5. 运行文档中的命令、示例编译或链接检查；无法执行的外部步骤明确标注未验证原因。

## Content Rules

- API 字段、返回值、状态码、环境变量和命令逐项对照代码，不凭记忆补全。
- 协议/parser/framer 的未知字段写 `unknown`/待真机确认，并说明需要什么证据。
- Markdown 与 HTML 双版本保持语义一致；避免复制两套会独立漂移的大段示例，能生成时优先生成。
- 发布说明描述用户可观察变化、兼容性和迁移动作，不罗列无意义内部重构。

## Result

列出更新的文档、对应代码事实和实际验证。若发现代码与文档冲突但用户只要求审查，报告冲突而不修改代码。

删除文档、示例或测试页面前确认目标与当前任务直接相关，并检查未提交改动；不能归因的内容不覆盖、不删除。
