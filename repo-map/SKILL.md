# Repo Map

目标：建立足以支持当前问题的证据化地图，而不是完整扫描仓库。

## Depth

- **Scan**：顶层目录、项目配置、入口和测试布局。
- **Feature**：围绕一个功能定位入口、状态/领域对象、服务、数据边界、测试和文档。
- **Architecture/Change**：确认项目引用、运行时注册、跨模块依赖和受影响验证点。

## Workflow

1. 用文件清单和构建配置确认技术栈与项目边界。
2. 定位运行、路由、DI、数据访问、测试和构建入口。
3. 从项目引用、import/export、注册和真实调用确认依赖方向；目录名只能作为推断。
4. 标记动态注册、生成代码、外部服务、循环依赖、跨层调用、缺测试和未知项。

输出关键入口、模块职责、依赖边和风险，并附路径证据。没有依赖分析能力时明确说明结论来自配置和引用推断；忽略 vendor、dist、build、coverage 和 cache。
