# Terminal Run

目标：用真实退出状态和关键输出验证明确假设。

## Workflow

1. 从项目配置和 lockfile 选择现有工具链，不混用包管理器。
2. 说明验证目标和工作目录，先运行最小相关命令，再按风险扩大范围。
3. 读取第一条关键错误，将结果归类为成功、构建/测试/运行错误、环境错误、权限或超时。
4. 失败后根据输出修复或缩小范围，不盲目更换方案；长任务持续观察并设置合理超时。

## Safety

- 运行未知 `test`、`dev`、`start` 脚本前检查其是否包含迁移、外部写入、数据清理或发布。
- 删除、Git 历史改写、commit/push/release、系统级修改、生产数据库和下载后执行脚本需要对应授权。
- Windows 删除/移动使用同一 shell，先解析并核对绝对目标路径。
- 开发服务器记录 URL、端口和进程；验证后关闭，除非用户要求持续运行。

## Reporting

摘要命令、CWD、退出状态、关键输出和验证范围。无法运行就报告真实环境错误；退出码为 0 不自动证明完整需求已验证。
