# Test Engineering

目标：用最小且稳定的测试集合证明用户可观察行为，避免只验证实现细节或追求无意义覆盖率。

## Routing

- **Bug regression**：先写能在修复前稳定失败的最小测试，再实现修复；测试名称描述触发条件和期望结果。
- **New behavior**：从公开入口验证正常路径、关键边界和失败语义；只在隔离外部依赖时使用 mock。
- **Refactor safety**：先确认已有测试覆盖行为，不够时补 characterization test，再调整结构。
- **Flaky test**：重复运行并隔离时间、随机数、共享状态、异步时序、网络和顺序依赖；不要直接增加固定 sleep。
- **Coverage request**：把未覆盖行映射到业务分支和风险；不为 getter、框架胶水或不可达代码堆测试。

## Workflow

1. 读取现有测试项目、命名、fixture、builder、mock、快照和运行命令，沿用本仓库约定。
2. 写清被测行为：给定什么输入/状态，经过哪个公开入口，应得到什么输出或副作用。
3. 选择最低成本且足以证明行为的层级：纯领域逻辑用 unit；边界映射/持久化/序列化用 integration；关键用户旅程才用 e2e。
4. 先观察目标测试按预期失败；如果它直接通过，检查是否测错路径或行为已存在。
5. 实现最小改动使测试通过，再运行同模块相关测试；高风险或交付前扩大到完整测试/构建。
6. 检查测试是否确定、相互隔离、失败信息清晰，并清理临时诊断代码。

## Test Boundaries

- **Unit**：验证纯计算、业务规则和状态转换；依赖可控、执行快速，不经过不必要的网络、文件系统或数据库。
- **Integration**：验证序列化、持久化、事务、框架配置或组件边界；测试替身必须保留当前结论依赖的真实语义。
- **Contract**：验证跨进程或第三方边界的请求、响应、schema 和兼容性，不依赖实现内部结构。
- **End-to-end**：只覆盖高价值用户路径和关键集成，不用大量脆弱 E2E 替代较低层测试。
- **Test doubles**：mock、stub、fake 只用于隔离非目标依赖；如果结论依赖某个真实 provider、协议或运行时行为，就在相应边界测试中验证。

## Stack Adaptation

先从项目文件和现有测试确认技术栈、测试框架与运行约定，再应用对应策略；不要仅因个人偏好引入新的测试库。

- **.NET / ASP.NET Core / EF Core**：领域与应用逻辑优先 unit test；endpoint、序列化、认证、EF 查询、事务和并发行为使用 integration/contract test。关系数据库语义应由相同或兼容 provider 验证，不用 EF InMemory 代替 SQL 行为证明。
- **Vue 3 / TypeScript**：composable、store 和纯函数验证状态与副作用；组件围绕可见 DOM、用户事件和公开 props/emits 测试，不断言私有 ref 或内部方法；关键路由与跨页流程再使用 E2E。
- **微信小程序原生开发**：业务逻辑与平台 API 分离后测试；页面验证 data、事件、生命周期和异步失败路径；依赖真机能力的行为在模拟测试之外明确保留真机验证项。
- **其他技术栈**：沿用仓库已有 runner、fixture、assertion、mock 和目录约定，依据相同测试边界选择层级；缺少现成测试体系时先给出最小引入方案和取舍。

## Result

说明新增或修改了哪些测试、它们证明什么，以及实际运行的命令与结果。无法先看到失败、无法运行所需环境或外部依赖时，明确列出证据缺口。

## Guardrails

- 不为让测试通过而放宽正确断言、吞异常、跳过用例或删除现有覆盖。
- 不把 mock 调用次数当成业务正确性的唯一证据，除非调用本身就是契约。
- 不编造生产数据、外部系统或第三方行为；未知条件使用明确 fixture 或标为待验证。
