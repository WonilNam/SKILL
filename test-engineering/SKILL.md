# Test Engineering

目标：用最小且稳定的测试集合证明用户可观察行为，而非实现细节或覆盖率数字。

## Routing

- **Bug regression**：仅当任务明确要求回归测试或用新测试锁定缺陷时，先写稳定复现问题的测试并确认按预期失败，再修复并验证通过。
- **Feature**：从公开入口覆盖正常路径、关键边界和失败语义。
- **Refactor**：先确认行为覆盖；不足时补 characterization test。
- **Flaky**：隔离时间、随机数、共享状态、异步、网络和顺序依赖，不用固定 sleep 掩盖问题。
- **Coverage**：把未覆盖代码映射到业务风险，不为框架胶水堆测试。

## Boundaries

优先选择能证明行为的最低层级：纯逻辑用 unit；持久化、序列化、事务和框架边界用 integration；跨进程 schema 用 contract；关键用户路径才用 E2E。测试替身只隔离非目标依赖，不能替代结论依赖的真实语义。

先读取仓库已有 runner、fixture 和命名约定。根据整体技术栈调整测试层级，但不把项目业务或设备细节写成通用规则。

## Guardrails

- 不通过放宽断言、吞异常、跳过用例或删除覆盖让测试变绿。
- 不把 mock 调用次数作为业务正确性的唯一证据。
- 报告测试证明的行为、实际运行结果和仍缺少的环境证据。
