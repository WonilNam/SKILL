# UI/UX

目标：交付符合现有产品、功能完整、可读且响应稳定的界面。

## Workflow

1. 读取同类页面、组件库、tokens、图标、路由和状态模式。
2. 明确用户任务、信息层级、组件边界、状态来源和关键交互。
3. 覆盖 loading、empty、error、disabled、权限、成功、失败和移动端状态。
4. 沿用现有技术栈；仅在收益明确时引入新依赖或重视觉效果。
5. 实际运行并检查关键 viewport、溢出、焦点、可读性、触控、reduced motion 和交互反馈。

## Design Rules

- 工具界面优先扫描效率和稳定布局；视觉效果不得牺牲内容与性能。
- 有设计稿时忠实实现；无设计稿时沿用现有系统，重大视觉方向才请求决定。
- 避免无功能 landing 壳、卡片套卡片和大装饰区域稀释核心操作。

## Safety

浏览器 QA 默认使用 local、mock 或 staging。支付、删除、发送、账号变更等真实副作用只检查界面状态，除非用户明确授权执行。

直接实现任务交付运行结果和 QA；设计/审查任务才输出结构化设计说明。
